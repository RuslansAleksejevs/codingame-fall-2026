# Простой бот TryAngle Catch

`bot.cpp` — выбранный v3-multispawn, один файл C++17. Команды: MOVE, SPAWN, WAIT.
На новых 50 картах с обеих сторон: 13/100 против khoufou и 0/100 против Lacoz, без собственных ошибок. Проверенный кандидат: submissions/baseline-v3-multispawn.cpp. Полный отчёт: experiments/2026-11-05-incremental/REPORT.md (PROJECT_REPORTED, 2026-11-05).
`opponents/wood1_port.cpp` — отдельный соперник для локальной проверки, адаптация алгоритма автора игры. Не включать его в наше решение.

## Как думает бот

1. Считает кратчайшие пути по текущим дорогам.
2. Выбирает доступные незахваченные треугольники; перебирает порядок трёх вершин и направляет ближайших свободных юнитов. На занятую врагом вершину нужно больше войск, чем у него сейчас.
3. При наличии лишних войск оставляет охрану захваченных вершин рядом с врагом.
4. Создаёт несколько новых юнитов за ход, расходуя каждый свой треугольник не более одного раза. До хода 150 стремится иметь столько войск, сколько домов на карте; затем снижает предел до половины, с хода 175 — до 3. Обычно сохраняет хотя бы один треугольник для дохода.
5. Каждый ход пересчитывает план. Не предсказывает действия противника, не использует атаки и изменение дорог.

Порог роста — простая эвристика. Версия с пределом 12 войск проиграла 7 из 8 учебных партий; увеличение предела дало 8 из 8 на тех же картах. Независимая проверка хранится отдельно.

## Файлы и повтор запуска

Рабочая папка команд — корень проекта «Соревнования».

```sh
python3 code/build_local.py
python3 code/run_matches.py --seeds 101:120 --out experiments/repeat-current
```

Папка результата должна быть новой. Каждая карта играется с обеих сторон; по умолчанию одновременно идут две партии.
Сохраняются исходники, копии бинарников, SHA256, версии, команды, счёт, сообщения движка и полные записи партий в JSON.gz.
`plan_us` — замер внутри нашего процесса от начала чтения хода до вывода, а не измерение CPU/лимита на сервере CodinGame. Параллельная локальная нагрузка влияет на него.

Для самого бота достаточно C++17:

```sh
clang++ -std=c++17 -O2 -Wall -Wextra -Wpedantic code/bot.cpp -o /tmp/tryangle-bot
```

Для локального движка нужны JDK17 и Maven. В этом сеансе использованы временные Temurin17.0.21+9 и Maven3.9.9 в `/tmp/tryangle-tools`; глобальной установки нет. После очистки `/tmp` нужно установить/распаковать их заново и указать `JAVA_HOME`, `TRYANGLE_MAVEN` (полный путь к `bin/mvn`), при необходимости `TRYANGLE_MAVEN_REPO`. Скрипт умеет находить исходную временную установку.
При отсутствии собранного движка Maven скачивает зависимости. Исходные Maven-тесты пропущены: наш проверяемый результат — реальные партии на неизменённом движке.

Источники инструментов: [Temurin17](https://adoptium.net/temurin/releases/?version=17), [Maven3.9.9](https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.9.9/).

## Основа локальной проверки

Неизменённые исходники: [eulerscheZahl/TryAngle-Catch, b691312](https://github.com/eulerscheZahl/TryAngle-Catch/tree/b6913124a10de328316ff42906448a18cb948431), папка `vendor/`. Архив получен 2026-11-05; Git-репозиторий не создавался.
Движок запускается в league3: доступны все действия, включая изменение дорог. `LocalMatch.java` лишь запускает два процесса и сохраняет GameResult.

Соперник — C++-адаптация `config/level1/Boss.cs`: выбор трёх юнитов для ближайшего треугольника, случайные движения остальных, активный SPAWN. Вместо C# Random используется mt19937, поэтому это **не точная копия живого босса**. Подробности происхождения также в самом файле.
Это проверка локальной силы и корректности; конкурсный рейтинг и совместимость с текущим конкурсным IDE отдельно не подтверждены. Отправка на платформу не выполняется этими скриптами.

## Публичные соперники и отдельные изменения

benchmark_public.py запускает оригинальных Lacoz и khoufou последовательно, по обе стороны. По умолчанию сравнивается замороженный v2; --source <файл.cpp> --label <имя> собирает конкретного кандидата. benchmark_ablation.py чередует несколько замороженных версий на одинаковых картах. Точные команды и источники — opponents/public/README.md, варианты нашего бота — variants/README.md.

analyze_incremental.py проверяет полноту серий, совпадение карт и исходников, отделяет технические исходы и сравнивает версии попарно по картам. Для текущей ветки сравнения: v2:v3, v3:v4, v3:v5. Повторный захват v4 и защита v5 — отдельные экспериментальные файлы; наличие варианта не означает его включение в основной bot.cpp.
